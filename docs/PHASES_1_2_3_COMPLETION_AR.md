# مصفوفة إغلاق المراحل 1 و2 و3

## Phase 1 — البنية الآمنة المشتركة

- [x] أنواع `Sample`, `Equipment`, `StandardReference`, `TestDefinition`, `TestRun`, `RawData`, `CalculationTrace`, `ValidationIssue`, و`ApprovalRecord`.
- [x] دورة حالات تفصل `Calculated` عن `Approved` وتمنع الاعتماد التلقائي.
- [x] تحقق مشترك لمستويات البيانات والفيزياء والرياضيات والهندسة.
- [x] محرك وحدات مركزي بوحدات SI الأساسية وتحويلات الأبعاد.
- [x] تشغيل عبر نموذج موحد خلف طبقة توافقية، مع بقاء المحرك القديم للقراءة والتوافق.
- [x] اقتراح تحديث خصائص المادة بدل الكتابة المباشرة قبل الاعتماد.
- [x] اختبارات regression للحالات الناقصة، التحقق، الحساب، الوحدات، التزامن والتخزين.

**الحالة: مكتملة ضمن نطاق البنية البرمجية المحلية.** لا تعني اعتمادًا مخبريًا رسميًا.

## Phase 2 — توسيع الفحوص الأساسية

- [x] تعريفات الركام الأساسية في المحرك الموحد.
- [x] تعريفات الإسمنت والمواد الرابطة الأساسية.
- [x] تعريفات الخرسانة الطازجة: slump، الكثافة، محتوى الهواء.
- [x] تعريف مقاومة الضغط للخرسانة المتصلدة.
- [x] تعريفات المونة: الانتشار ومقاومة الضغط.
- [x] حفظ خطوات الحساب والوحدات والتحقق مع كل تشغيل.
- [x] إبقاء معايير القبول غير مفعّلة حتى تُسجّل نسخة معيار وقاعدة قبول صريحة.

**الحالة: مكتملة كتعريفات ومحركات قابلة للتشغيل.** يلزم إدخال مواصفات المشروع الفعلية قبل تصنيف أي نتيجة Pass/Fail.

## Phase 3 — الحوكمة والتقارير

- [x] هوية وملكية اختيارية متوافقة مع local-first.
- [x] نسخ immutable مع revision وhash ومقارنة.
- [x] سجل تدقيق مستقل وتصدير JSON/CSV آمن.
- [x] مصفوفة الصلاحيات وفصل واجب الإنشاء عن الاعتماد.
- [x] تقارير تحتوي verification/approval/integrity metadata.
- [x] سجل مركزي للمعايير مع حالة الإصدار وقواعد القبول.
- [x] سجل مركزي للأجهزة مع حالة المعايرة ومنع استخدام الجهاز المنتهي.
- [x] اختبارات E2E للوصولية والاستعادة والأداء.

**الحالة: مكتملة ضمن نطاق local-first والحوكمة البرمجية.** OAuth، التخزين السحابي، tenancy، والتوقيع الرقمي الخادمي تبقى نطاق SaaS لاحقًا.

## التحقق

الأوامر المطلوبة قبل الانتقال إلى Phase 4:

```bash
npm run lint
npm test
npm run build
npm run test:e2e
npm run test:performance
```

> لا تستخدم النتيجة البرمجية وحدها كاعتماد هندسي. يجب على المختبر تحديد المعيار والإصدار وقاعدة القبول وصلاحية الجهاز قبل اعتماد نتائج حقيقية.
